Move on Sui: How Its Rules Protect Coins

What is the Move language on Sui? Move is a resource-safe smart-contract language; Sui Move organizes assets as objects with explicit ownership.

Crypto Bulletin Newsroom Nov 25, 2026 · 20:11 UTC 2 min read

Move helps you understand how Sui smart contracts handle assets: its type rules prevent a coin from being copied or silently discarded. Sui uses an object-centred version called Sui Move, where assets have their own identities and ownership.

A bridge moves tokens across chains; Suibridge uses lock-and-mint to transfer supported assets from Ethereum to Sui. For the mechanics of that route, see Suibridge’s Ethereum-to-Sui transfer process; Sui Move, by contrast, defines how assets behave once represented on Sui.

Where did Move come from, and what does Sui change?

Move was developed for Facebook’s Diem project, then called Libra, to represent digital assets as resources with rules against copying or implicit loss. The 2019 paper “Move: A Language With Programmable Resources” describes those protections as part of the language’s type system.

Move is also commonly described as Rust-inspired. Mysten Labs built Sui, whose mainnet launched in May 2023, and adapted Move for Sui’s object model.

In a traditional account-based model, asset balances can be entries in a mapping. Sui instead stores data as objects addressed by unique IDs. Each object has an owner, and can be address-owned, shared or immutable, according to Sui’s documentation.

This changes how a contract works with state: it receives objects as inputs and can update, transfer or consume them. Sui Move’s ownership model makes the assets themselves the units a transaction handles.

How does Move stop a coin from being copied or lost?

A Sui Coin<T> is an object with the key and store abilities, but without copy or drop. The Move Book explains that copy permits duplication and drop permits a value to be discarded; without them, the compiler rejects code that tries either operation on a coin.

Take a coin passed into a contract. The code must account for it: it can transfer the coin, split it into coins, merge it with another coin, or burn it through the applicable operation. It cannot leave a duplicate behind or silently make the original disappear.

That is the practical reason Move treats assets as typed resources rather than ordinary numbers in a balance table: the compiler enforces key handling rules while developers write the contract.
