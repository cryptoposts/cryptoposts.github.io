Canonical Bridged Tokens Depend on the Route

A canonical bridged token is the network-recognized representation of an asset on a specific bridge route. Learn how to identify its origin and mapping.

Crypto Bulletin Newsroom Nov 17, 2026 · 09:32 UTC 2 min read

A canonical bridged token is the representation that a network or project recognizes as standard for an asset on a particular bridge route. On Gnosis Chain, Gnosis Bridge uses Omnibridge to map assets sent from Ethereum to destination representations. Different bridges can create separate representations of the same source asset, so the recognized token depends on the route.

Canonical status belongs to a route and network

Canonical describes recognition; native describes where a token is issued. A token can be canonical on Gnosis Chain as the recognized bridged representation of an Ethereum asset, while a native token is issued directly on Gnosis Chain.

That status has a scope. To identify it, name both the network that recognizes the token and the route covered by that recognition. The same source asset may have multiple destination tokens when it arrives through different bridges.

  • Source asset and origin network
  • Bridge route
  • Destination network
  • Mapped destination representation

These details connect the destination token to the asset it represents. Gnosis Chain’s Omnibridge documentation describes canonical bridged representations and provides token registries where users can check the chain of origin.

Omnibridge maps Ethereum assets to Gnosis Chain tokens

Say you deposit an ERC-20 from Ethereum through Omnibridge. In the lock-and-mint model, the bridge holds the source tokens and issues a destination representation on Gnosis Chain; Omnibridge maintains mappings between source tokens and those destination representations.

That mapped token is the representation recognized for that asset and route on Gnosis Chain. Another bridge may issue a different token for the same underlying asset. A familiar name or symbol alone does not identify which representation a network recognizes.

Use the official token mappings and Omnibridge documentation to check the destination token’s origin and bridge route. That check tells you whether the token in your wallet is the representation recognized for the route you intended.
