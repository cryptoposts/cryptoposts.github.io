Does speeding up a pending Gnosis Bridge deposit change it?

Speeding up a pending bridge transaction keeps its token, amount and recipient unchanged; MetaMask raises the fee, and the mined replacement has a new hash.

Crypto Bulletin Newsroom Nov 25, 2026 · 17:02 UTC 2 min read

A pending Gnosis Bridge deposit sped up in MetaMask keeps its token, amount and recipient: Speed Up replaces the Ethereum transaction at the same nonce with a higher fee, and the version that mines makes the original deposit.

Say you set up a deposit of 10 tokens to a chosen recipient. MetaMask’s Speed Up submits a replacement with the same transaction nonce and deposit data, but a higher transaction fee to seek earlier inclusion. The replacement gets a new transaction hash. That choice determines whether the transfer continues or is canceled; see Speed Up or Cancel a Gnosis Bridge deposit for how each option affects a pending transfer.

The replacement keeps the deposit details

Ethereum uses a transaction nonce to order transactions from an account. Only one transaction with a given nonce can be included, so the original and its Speed Up replacement compete to be the version that gets mined.

For the 10-token deposit, the replacement retains the transfer data specifying the token, amount and recipient. Raising the fee changes what you offer to have the transaction included; it does not rewrite those deposit details.

A mined bridge deposit calls the bridge contract with transaction data that specifies the transfer. With Gnosis Bridge, that call is what carries the deposit details into the bridge process. Speed Up resubmits the pending call with a higher fee and the same nonce.

The mined hash identifies the deposit

When one version mines, that transaction emits the deposit event and creates the bridge message. The other version cannot also be included with the same nonce, so it does not create a second deposit.

To see which version took effect, look up the original transaction hash and the replacement hash in Ethereum transaction activity or a block explorer. The mined one has a confirmed status and the deposit event; the other does not show a second completed deposit. The new hash belongs to the replacement, even though its deposit details match the original.

In short, Speed Up changes the pending transaction’s fee and hash. It keeps the deposit itself as originally configured, provided the replacement is the version that mines.

  • Speed Up uses the same nonce and deposit data, with a higher fee.
  • The mined version has a new transaction hash and creates the deposit event and bridge message.
  • Only one version with that nonce can be included.
