Stalled Bridge Transactions: How Nonce Management Works

A stalled bridge transfer may be waiting on a source-chain nonce or a separate destination step; identify which one before replacing or cancelling anything.

Crypto Bulletin Newsroom Oct 17, 2026 · 03:16 UTC 3 min read

A stalled bridge transaction needs nonce management on the chain where it was sent: the account nonce orders transactions from that wallet, and a later transaction can wait behind an earlier one. Ethereum’s account documentation describes the nonce as a counter that allows only one transaction with each account nonce to execute. A manta bridge guide explains the cross-chain steps around that source transaction. The distinction matters because a bridge transfer can involve both a wallet transaction and a separate message handled by the bridge.

What does a nonce mean in a stalled bridge transaction?

A nonce is the sender’s transaction number on one chain, not a universal bridge tracking number. If transaction 12 is still pending, a wallet may hold transaction 13 until the earlier transaction is included or replaced. Some bridges also show a message ID or sequence value; that belongs to the bridge’s own tracking and does not replace the wallet nonce.

Start by checking the source-chain transaction in a block explorer. Confirm its status, sender address and nonce, then compare the wallet’s confirmed and pending transaction counts. A pending source transaction points to a different problem from a confirmed source transaction whose bridge message has not completed.

How can you clear a pending source transaction?

If the source transaction is still pending, the wallet may let you resubmit it with the same nonce and a higher fee. Ethereum’s support guidance describes this as speeding up a transaction; node fee rules determine whether the replacement is accepted. The replacement can repeat the original bridge call or, where the wallet supports it, attempt a cancellation using that nonce.

  • Check the transaction status and nonce on the correct source chain.
  • Use the wallet that controls the sending address to replace or cancel it.
  • Review the replacement details before signing, especially the destination address and call data.
  • Wait for confirmation and check the explorer again before taking another action.

A cancellation is not guaranteed: if the original transaction gets included first, it may still execute. Replacing a transaction also does not erase a bridge transfer that has already been confirmed.

What if the source transaction is already confirmed?

Once confirmed, the source-chain transaction has consumed its nonce. Sending another transaction with that old nonce cannot reverse it. Check the bridge’s status for the confirmed transaction or message ID, then follow that protocol’s process for a delayed or failed destination step.

The practical rule is to diagnose the stage before acting: use same-nonce replacement only for a transaction that is still pending on its source chain. If it is confirmed, investigate the bridge message instead.
