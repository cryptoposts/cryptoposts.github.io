How to switch RPC endpoint in MetaMask for a stuck transaction

To switch an RPC endpoint in MetaMask for a stuck transaction, choose a working endpoint for the same network, update its RPC URL, then check the hash before replacing anything.

Crypto Bulletin Newsroom Nov 24, 2026 · 12:33 UTC 3 min read

To switch an RPC endpoint in MetaMask for a stuck transaction, choose a working endpoint for the same network and replace that network’s RPC URL in settings.

An RPC endpoint is the node MetaMask contacts to read network data and submit transactions. A slow or unavailable endpoint can make network activity hard to read, but changing it does not cancel or speed up a transaction already submitted.

Chainlist lists EVM networks and their RPC endpoints. Our Chainlist RPC pending transaction coverage adds background on separating endpoint problems from a transaction that needs its own fix.

Use an endpoint for the same network

Find the network you already have selected in MetaMask, then note its Chain ID and choose an RPC endpoint listed for that network. The Chain ID must match the network you intend to use; an endpoint serving a different chain can send MetaMask to the wrong network.

MetaMask’s network settings include an RPC URL and a Chain ID. You can compare the listed Chain ID with MetaMask’s value. The JSON-RPC method eth_chainId also reports the chain ID served by an endpoint.

Open MetaMask’s network settings and edit the network’s RPC URL, or add another endpoint for that network. Labels and menu locations vary by MetaMask version. Save the change, select the network again, and look up the transaction hash in a block explorer for that network.

A new endpoint may not have the pending transaction

Say you sent a transaction on Ethereum, then switch MetaMask to another Ethereum endpoint. The new node may not have received or indexed the transaction yet, so it may not show up there immediately. Search the hash in an Ethereum block explorer before trying to send anything again.

If the explorer shows the transaction as pending, the transaction is still in the network’s queue. A low fee can keep it pending even when MetaMask can read the network through the new endpoint. Use MetaMask’s replacement controls, if available, to replace the pending transaction with one using a higher fee or the same nonce. Follow the wallet’s prompts and confirm the replacement details before submitting.

If the explorer finds no transaction, confirm the network and hash before taking further action. A different endpoint can help MetaMask read and submit through another node; the transaction’s fee or nonce may still need attention.

To continue:

  • Keep the transaction hash and identify the network in MetaMask.
  • Choose a listed RPC endpoint with the matching Chain ID and update the RPC URL.
  • Look up the hash in a block explorer; use the wallet’s replacement controls if it remains pending.
